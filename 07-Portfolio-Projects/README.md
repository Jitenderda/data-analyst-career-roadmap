# Portfolio Projects

This folder is the home for completed, reviewed Data Analyst portfolio projects.

Projects will be added progressively after the relevant skills have been taught and practised. Do not create projects just to fill the portfolio; each project must demonstrate independent analytical work.

## Project Standards

Every substantial project should include:

1. **Business problem** — What question or problem are we trying to solve?
2. **Objective and scope** — What will the analysis cover?
3. **Dataset and data dictionary** — What does the data contain, and what does each field mean?
4. **Data preparation** — What quality issues were found and how were they handled?
5. **Analysis** — What methods, formulas, queries, or code were used?
6. **Visualisation** — What charts, tables, or dashboard views communicate the results?
7. **Findings** — What does the evidence show?
8. **Recommendations** — What practical actions follow from the findings?
9. **Limitations** — What cannot be concluded from this dataset?
10. **Reproducibility** — Can another person understand and reproduce the work?

## Suggested Project Areas

These are possible project themes, not assignments to start immediately.

| Project Theme | Possible Tools | Example Business Questions |
|---|---|---|
| Customer Enquiry Analysis | Excel, SQL, Power BI | Which channels, cities, or periods generate the most enquiries? |
| Complaint & Resolution Analysis | Excel, SQL, Power BI | Where are delays occurring, and what affects resolution rates? |
| GPS & IoT Activation Analysis | Excel, SQL, Power BI, Python | Which factors are associated with stronger activation performance? |
| Dealer Performance Analysis | SQL, Power BI | Which dealers perform well across volume, conversion, and service metrics? |
| End-to-End Business Analysis | SQL, Python, Power BI | What insights and recommendations emerge from combining multiple datasets? |

## Project Folder Template

Each project can use a structure like this:

```text
project-name/
├── README.md
├── data/
│   └── README.md
├── analysis/
├── visuals/
└── outputs/
```

Only publish datasets that are public, synthetic, or appropriately anonymised and approved for sharing. Never publish confidential company information, customer personal data, credentials, or proprietary records.

## Project Review Checklist

- [ ] The business problem is clear.
- [ ] The dataset and fields are documented.
- [ ] Data quality checks are explained.
- [ ] Analysis is correct and reproducible.
- [ ] Visuals are appropriate and readable.
- [ ] Findings are supported by evidence.
- [ ] Recommendations are practical and justified.
- [ ] Limitations are acknowledged.
- [ ] The README is understandable to a recruiter.
- [ ] The work has been reviewed and corrections completed.

## Project Register

Maintain the project status in the repository's `PROGRESS-TRACKER.md`.

**Quality principle:** A small number of complete, defensible projects is more valuable than many unfinished or copied projects.
